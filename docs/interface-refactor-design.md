# 对话驱动的四模块白板工作台：界面重构方案

设计日期：2026-10-11。状态：四模块工作台已接入业务代码；本文同时记录实现基线与后续完善方向。

## 1. 核心结构

用户已明确：无限画布上始终只有四个模块白板，分别对应 DXF 底图、空间节点图、仿真指标、生成方案。对话持续更新相关模块；设计迭代不增加、复制或重建白板。

层级：会话 → 一个 tldraw 无限画布 → 四个独立模块白板 → 模块内容及其内部历史版本。初始化会话时一次性创建四个稳定 ID 的白板，未有内容的模块展示空状态。用户可以移动、调整白板尺寸和标注；模块白板不能删除或复制，自由标注不计入模块白板数量。

主入口为左侧 Agent 对话；右侧四个白板展示业务状态，也支持直接专业编辑。候选方案及比较界面属于生成方案模块，需求、底图和工况历史属于对应模块。

## 2. 页面与视觉

- 顶部：项目/会话、Agent 提供方、运行及保存状态。切换提供方沿用会话隔离规则。
- 左侧：对话栏默认约 340 px，支持调整和折叠；消息独立滚动，输入固定在底部，包含附件及模块/空间引用。
- 右侧：无限画布，占据剩余空间；提供选择、平移、缩放、适应全部、模块定位与标注。
- 默认布局：DXF 白板左上、节点图白板左中、指标白板左下、方案白板右侧放大。四块各自有边界、标题、状态和局部操作，不再放入一个共同的白板外框。
- 白板位置可自由拖动，初始三对一布局只是默认排列。关闭详情回到原白板，相机和位置不被任务更新重置。
- 复杂编辑使用画布区域内展开视图，左侧对话保持可用；窄屏采用对话/画布切换和模块定位。

视觉采用用户指定的纯白底色和淡色科技风：整体、顶部、对话区、画布、四块白板及标题栏均为 #FFFFFF。冷蓝强调色 #3375C4，主文字 #243750，次文字 #61748D，边界 #DCE5F0，选中底色 #EDF5FF。科技感来自精细网格、定位角标、线性图标、等宽数值和柔和阴影。

白板圆角 6 px，工作台外框 10 px，正文 14 px，次信息 12 px，技术标识 11 px。避免大面积彩色底板、霓虹和持续扫描动画；状态通过文字与符号表达。

## 3. 四个白板的职责

| 固定白板 | 内容 | 内部操作及历史 |
| --- | --- | --- |
| DXF 底图 | 文件、轮廓、构件、单位、图层、解析状态 | 查看、重新上传、替换底图；底图版本历史 |
| 空间节点图 | 房间用途、面积范围、邻接关系、采光要求、约束检查 | 编辑节点与关系、保存/切换需求版本 |
| 仿真指标 | 目标和工况、当前查看方案的实测值、未达标项、运行状态 | 配置、运行、取消、重试；按方案与工况查看结果历史 |
| 生成方案 | 当前查看候选、平面/三维/结果图、几何状态 | 方案版本选择、候选比较、采用、导出 |

三条依赖线表达：DXF 约束几何边界，节点图约束空间关系，指标约束评价目标。连线绑定四个稳定模块 ID；移动白板时保持关联。仿真针对具体候选执行，结果回写指标模块，热力图可在方案模块查看。

模块白板布局与业务版本分离。生成方案时保存底图、需求和工况的版本快照；切换历史候选显示其输入来源与关联评价，不隐式覆盖当前编辑中的需求和工况。

## 4. 对话驱动流程

1. 打开会话：四个白板均存在，未配置模块显示空状态。
2. 上传 DXF：填充已有 DXF 白板；更新底图版本，影响下游有效性。
3. 描述需求：Agent 提取空间和目标，分别更新已有节点图、指标白板；单位缺失或约束冲突在对应模块及对话显示。
4. 生成候选：冻结输入版本，已有方案白板显示任务进度；有效候选到达后新增内部版本 r1/r2，而非新建白板。
5. 仿真评价：指标白板显示所选方案的执行进度和结果，方案白板展示相关热力图。几何成功、仿真失败时保留候选并提供重试。
6. 引用模块或空间：输入区显示“空间节点图白板 / 主卧”或“生成方案白板 / r2”；后续消息带明确对象和版本。
7. 继续修改：更新相关输入模块，生成新的方案版本，四个白板的 ID、位置和数量保持不变。
8. 比较和采用：在方案白板内展开两个候选进行同工况比较；采用后更新会话的 currentRevisionId，历史版本继续保留。

Agent 消息的产物链接定位模块，并可以指定方案版本。普通问答、生成、优化和评价都不增加模块白板。Agent 更新业务内容，不擅自重排用户布局；用户主动移动相机后不抢夺视角。

## 5. 输入变更和版本规则

- 三类状态分开管理：当前编辑的输入、当前查看的候选、当前已采用的方案。
- 每个候选记录 inputRevisionId、briefVersionId、configVersionId 和 parentRevisionId，可恢复当时输入。
- 更改底图、需求或工况不覆盖历史候选和结果；将当前候选与新输入的差异明确标为“基于旧输入”，提供重新生成/重新评价入口。
- 选择旧候选时，指标模块显示该候选及其关联工况的结果；当前目标另作标识，避免把旧实测值与新工况混用。
- 迟到结果存入其对应历史版本，不切换用户正在查看的方案。检查 taskId、revisionId、输入及工况版本后才更新当前视图。
- 切换历史版本属于查看；“恢复为当前需求”或“采用此方案”是独立的业务动作。

## 6. 专业编辑与技术结构

每个模块可以用一个自定义 tldraw Shape 承载概览、稳定标题与局部动作；模块需要多个子内容时，可使用独立 frame，frame 内组织内容。四个模块分别是四个顶层白板，不使用共同的外层 frame。

单击选择/引用；标题栏拖动白板；双击或打开进入内容编辑。概览状态由 tldraw 处理画布手势，编辑状态由内部组件处理鼠标、滚轮和快捷键；Esc 返回概览。首期节点图及三维查看器优先在展开视图中编辑，避免嵌套缩放冲突。业务依赖线由系统维护，手绘连线只作标注。

现有 React 18 + Vite、Chat、Composer、Viewer、React Flow 节点编辑器、仿真组件及 NDJSON API 可复用。建议结构：

```text
WorkbenchShell
├── WorkbenchTopbar
├── AgentPanel
│   ├── Chat + ModuleMessageLink
│   └── Composer + ContextReferences
└── DesignCanvas (tldraw)
    ├── DxfBoardShape
    ├── SpaceGraphBoardShape
    ├── SimulationBoardShape
    ├── SchemeBoardShape + RevisionPicker
    └── ModuleFocusView / SchemeComparisonView
```

tldraw 管理白板的位置、尺寸、选择、相机和标注。业务 store 管理文件、需求、方案、仿真、版本和任务。shape 中只保存模块 ID、资源/版本引用和展示配置；DXF、大网格和仿真数组放在业务资源中。DXF 和方案白板直接挂载现有 Viewer 的真实 WebGL Canvas，节点白板直接复用 SpaceGraphCanvas 的完整 ReactFlow 渲染（含入口和全部关系）；不再单独绘制 SVG 概览。缩到紧凑状态或离屏时由画布减少渲染，展开详情后使用完整交互查看器。

## 7. 数据与事件建议

```ts
type ModuleKind = 'dxf' | 'spaceGraph' | 'simulation' | 'scheme';

interface ModuleBoard {
  id: string; // 在一个会话内稳定，生成/评价不改变此 ID
  sessionId: string;
  module: ModuleKind;
  artifactId?: string;
  status: 'empty' | 'ready' | 'running' | 'stale' | 'failed' | 'cancelled';
}

interface DesignWorkspace {
  sessionId: string;
  boardIds: Record<ModuleKind, string>; // 恰好四个模块
  currentRevisionId?: string; // 已采用
  viewedRevisionId?: string; // 当前查看
}

interface SchemeRevision {
  id: string;
  parentRevisionId?: string;
  inputRevisionId: string;
  briefVersionId: string;
  configVersionId: string;
  sourceMessageId: string;
  modelResourceRef: string;
}
```

运行状态、几何校验、仿真完成和指标达标分别记录。历史文件、需求和评价也有各自版本实体，通过资源引用关联，不把全部历史放入画布 shape。

Agent 文本用于对话，模块内容通过验证后的结构化事件更新。首期适配已有 progress、design、error、done；后续增加 module.updated、scheme.revision.created、task.progress、evaluation.completed。模块白板创建只发生在会话初始化及缺失修复阶段。

事件携带 sessionId、module/boardId、taskId、revisionId、输入/工况版本与幂等 eventId。对话上下文包含所引用模块、artifactId/revisionId 和选中的 spaceId；Agent 通过受约束的业务 command 请求动作，不输出任意页面 HTML 或脚本。

## 8. 保存与异常

服务端保存画布快照和恰好四个白板的索引；业务资源与历史版本单独保存。文档恢复时验证模块完整性，补齐缺失模块并去重，保留已存在白板的稳定 ID 和用户布局。

相机、选择、展开状态和栏宽属于本地偏好；画布变化节流保存，生成完成及退出编辑立即保存。显示保存中/已保存/失败重试，自定义 shape schema 和迁移版本化。正式保存不只依赖本机浏览器缓存。

tldraw 撤销只处理布局和标注；业务修改通过版本回退。取消和失败保留已完成内容，在对应模块提供重试；任务不会清空四个白板，也不会自动采用候选。

## 9. 实施与验收

1. 验证 tldraw 版本与 React 18 构建兼容性、自定义 shape、独立白板/依赖绑定、编辑事件隔离、快照恢复及生产许可。
2. 搭建白底工作台，初始化四个稳定白板，完成定位、引用、空状态和保存。
3. 接入上传、需求编辑、生成和仿真；新增方案内部版本选择、评价关联与比较采用。
4. 完成输入变更提示、历史恢复、任务取消、迟到结果处理、专业编辑和重型组件懒加载。

核心验收：空会话即有四个模块白板；反复上传、对话、生成、优化和评价后始终四个；模块 ID 与用户布局保持稳定；候选只增加方案内部版本；切换候选正确显示关联评价及输入来源；当前编辑、当前查看、已采用状态互不混淆；刷新恢复四个白板、布局与版本引用；失败及迟到结果不污染当前视图。

## 11. 实现与验证记录

已实现：tldraw 5.5.2 + React 18、纯白工作台、四个稳定 ID 的模块白板、绑定依赖箭头、复制/删除保护、拖动/缩放/标注、模块定位、模块与空间引用、内部方案版本选择和采用、底图与候选分类、专业模块展开、聊天任务取消、消息产物链接、对话栏调宽及移动端视图切换。节点编辑状态在详情关闭期间保留；WebGL 查看器只在相关详情可见时挂载，专业模块代码按需加载。

布局通过本机 IndexedDB 和服务端 canvas.json 保存。服务端验证恰好四个模块白板，限制文档大小并原子写入。已打开的会话、当前底图、当前查看及已采用版本、最近消息在浏览器恢复；这里的消息与已采用版本缓存仍是单机偏好，不是跨设备会话目录服务。

浏览器验证覆盖：真实 DXF 导入、需求改名与保存、关闭详情保留未保存修改、版本切换保留当前输入、删除/复制保护、刷新恢复、模块引用及 320/375 px 布局。使用 Echo 和仓库示例进行验证，未额外发起真实模型计费任务。

类型检查、生产构建及新增画布/模型测试通过。全量测试为 350/353 通过；三项未通过涉及现有住宅采光模拟未完成、自动交通区断言、承重墙续接断言，具体结果保存于执行时的测试日志。几何求解与采光引擎的这些问题未在界面重构中修改。

生成前置条件：工作区不提供默认示例方案入口。只有导入固定 DXF、配置空间节点并至少启用一个采光指标、保存需求版本后，才可生成候选。对话生成与节点生成都提交冻结的需求版本；工作区请求由服务端再检查前置条件。版本选择只展示与当前底图关联且带需求版本的候选，历史示例数据不会自动显示。仿真指标详情在生成前可进入采光目标与工况配置，实际评价在生成后运行。

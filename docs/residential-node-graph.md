# 住宅需求节点图与布局生成

## 主流程

上传固定住宅 DXF（轮廓、承重墙、入户、窗）→ 编辑空间需求节点及关系、使用参数、采光目标 → 保存带底图哈希的需求版本 → Agent 提供布局意图 → 算法联合分配障碍网格与门连接 → 精确墙体与净空间验证 → 交付几何候选并自动运行室内采光评价。

节点图存在于生成前，position 只是图编辑坐标。固定 DXF 构件不会被 Agent 或求解器修改。浏览器可恢复最近固定底图及已保存需求，切换平面/节点图不丢失当前编辑。

## 可编辑需求与约束分级

房间保留稳定 ID、名称、类型、最小/期望/最大净面积、外窗要求及采光目标。房间面积范围与 hard 关系必须满足；soft 关系与窗/方位偏好参与提示和评分。必窗房间须关联完整固定窗，不能将一扇窗横跨两个房间。

布局参数面板提供初步网格尺寸（默认0.5m）、通行净宽（0.9m）、新增门宽（0.9m）及门前净空深度（0.9m），均可编辑。这些是产品使用要求，不是建筑法规认证。布局网格与采光测点间距是两个独立参数。

默认只有客餐厅和交通空间允许穿行；每个房间可单独修改 allowThrough。直接连通需真实门连接；相邻需共享墙边界；public_access 需沿允许穿行的空间到达；no_direct 禁止直接开门。所有房间须具有入户通路，但不强制每个房间均走公共路径。套卫可通过主卧进入；若还要求经公共空间可达，应明确指定允许穿行的主卧。

住宅不必须有走廊。求解器可以让客餐厅承担通行，也可按需生成 solver-circulation。独立交通区面积、服务对象、冗余及隔墙长度参与评分。

不再对新网格流程强加按房间类型写死的主体尺寸。用户可在房间节点开启 bodySize（可交换宽深方向），开启后作为硬要求。尾部、细长形状一般是品质提示；允许穿行的空间如果没有满足所设净宽的主体，或主体被窄颈分隔，仍拒绝。新旧检查通过 qualityChecksVersion 区分。

## Agent 意图协议

新提示词仅要求：

```json
{"schemaVersion":2,"rationale":"功能分区和动线意图","roomOrder":["room-living","room-main"],"circulation":"auto","preferences":[{"roomId":"room-main","side":"south","windowId":"W1"}]}
```

roomOrder 恰好包含全部需求房间，表示安排优先级，不是固定拓扑；circulation 为 auto 或 prefer，均不是必须有走廊；位置偏好可以调整。Agent 不输出坐标、墙体或切分树。底图、需求、使用参数、采光工况直接放入提示；不依赖旧 prompts/skills 或文件工具。

历史 schemaVersion 1 切分策略保留解析与本地回放兼容，采用旧二叉切分器；新生成接口只接收 schemaVersion 2 网格策略，旧协议仅可本地回放，不会让Agent退回旧求解器。报告及候选元数据明确标记实际使用的求解方式。

## 障碍网格与精确几何

第一阶段支持正交住宅轮廓、轴向固定墙体。网格在0.5m等粗间距之外，插入轮廓内侧与固定墙面坐标。每个格子通过精确多边形交集检查，只有完全处于可用空间的格子可分配，承重墙不会因为比网格细而消失。

需求房间的候选是连续的矩形格子集合，面积范围、完整窗和固定入户归属参与候选构造。矩形房间可贴合固定构件，精确减墙后可形成简单L形边界。随机化束搜索保留不同位置与窗口分配，客餐厅与按需交通由剩余可用区域形成，可以是正交凹多边形。不是任意形状的逐格自由生长，也不是完备求解。

公共区域分解可以借助固定承重墙轴线，具体房间坐标不由 Agent 指定。形成有厚度的隔墙后，精确布尔运算计算房间净边界与净面积。所有需求房间、固定构件及模型规范再次验证，不能直接交付粗网格。

每个完整候选在保留前联合搜索门位与通路。门位加入房间边界转折、墙段中点和0.1m采样点；同时搜索门位、开启侧及铰链方向，冲突时回退。检查门两侧净空、门扇与房间/墙体、门扇彼此碰撞。门位搜索有预算，失败不会被描述成数学无解。

求解首阶段需要至少一个允许穿行的入口承接空间。斜墙、任意房间多区域生长、全面家具布局与建筑规范检查仍不属于此阶段。网格候选规模、束宽、时间和门位组合搜索均有界，成功率需用案例集统计。

## 住宅默认预设

五房间：客餐厅20/28/40㎡、主卧10/14/22㎡、次卧10/12/20㎡、厨房5/7/12㎡、公共卫生间3/5/8㎡（最小/期望/最大）。主次卧必须有窗，客餐厅和厨房尽量有窗，卫生间不要求窗。默认入户直接进入客餐厅，其他房间经公共空间可达；客餐厅直接连接厨房，厨房与卫生间尽量相邻，厨房禁止直接连接卧室。

主次卧和客餐厅采光预设300 lx、50%达标面积，优先级尽量。全局为标准阴天天空、室外参考照度10,000 lx，可编辑测点和材料参数。预设是可编辑需求，不是规范结论。

## 空间分配阶段的硬连接检查

必须直接连通的私有房间优先成组安排，如卧室与套卫。新增房间时检查已分配房间之间是否保留足够开门宽度的共享边界，并向前检查未分配的关联房间是否仍有兼容候选。与客餐厅必须直连的房间需保留未被其他房间、固定墙或外边界占用的边界，避免全部摆完才发现连接被切断。

这些是必要条件筛选，不替代完整几何验证；墙厚、门前净空、门扇碰撞和实际可达性仍由最终检查确认。相邻、经公共空间可达和禁止直接连通继续沿用原验证规则；用户硬要求不降低。solver-report.json 中 earlyConnectionPrunes 保存提前淘汰分支的原因与计数，报告面板可展开查看。

## 重试、报告与故障恢复

最多三轮布局策略尝试，另有最多两次独立格式修复，格式错误不会抹去累计布局失败反馈。每轮Agent最多4分钟、90秒无真实活动终止；总Agent流程最多12分钟，前端13分钟取消。几何搜索首阶段20秒预算，搜索超时作为可重试失败，连同具体连接冲突与累计失败记录反馈Agent调整窗偏好、分区和顺序，最多仍为三个布局轮次；不支持的底图、需求或网格规模及无单房间候选仍直接终止。超时明确记录；成功可在预算内交付已找到的最优保留候选。

版本目录保留 generation-brief.json、strategy*.json、agent-response*.txt、solver-attempt*.json、solver-report.json、validation.json 及 generation-state.json。失败报告区分无单房间候选、不支持的几何/需求、搜索未找到解与预算耗尽，记录有界数量的拒绝候选及原因。汇总原因可能来自不同候选，不能当成同一平面上的全部问题。

界面的求解报告显示搜索方式、网格、预算、失败计数、软关系与品质提示；被拒绝候选可叠加固定承重墙预览，明确不是有效方案。新候选带 geometryStatus/qualityStatus、solver、qualityChecksVersion；旧候选不会追溯被认定通过新检查。

取消、断流、服务重启保持原故障恢复逻辑，保留日志与需求，不覆盖历史候选。

## 采光边界

采光照度阈值、达标面积比例与优先级完整交给 Agent，并冻结为生成需求。几何评分不代表采光性能；生成后由Radiance进行独立评价。按仿真反馈重新布局仍属于下一阶段。

## 2026-10-09 单方案采光评价

单方案生成后自动运行采光、按面积比例评价并展示节点指标及热力图已接入。以上“采光边界”段落中的对应项由本节更新；多候选筛选和仿真反馈重新布局仍未实现。实现与假设见 [单方案住宅采光评价](residential-daylight-evaluation.md)。


## 阳台需求节点

新增房间和空间类型选择器支持 balcony（阳台），可编辑面积、连接关系、外窗要求和采光目标。新增阳台默认净面积2/4/8㎡（最小/期望/最大），默认不作为穿行空间，不开启采光目标，均可调整。当前按固定轮廓内部的需求区域求解；仅类型新增不自动改变楼板、外墙开口或空间封闭状态。


## 交互式节点连接

节点左右两侧有连接圆点，可从圆点拖到另一个节点卡片或圆点并松开，也可依次点击两个圆点（键盘聚焦后Enter同样可用）。拖动过程中显示预览连线和目标高亮；Esc、指针取消或拖到空白处取消连线。拖动卡片本体仍只移动节点。

完成连接后在关系面板设置类型与优先级并“应用关系”，再保存需求；未应用的关系显示虚线预览，保存与生成暂时禁用。已有同类关系不会重复添加；同端点的已有无向关系可直接打开编辑，public_access 保留方向。入口节点可以参与连接，但固定锚点不可移动。


## React Flow画布

交互画布已迁移到 @xyflow/react。支持滚轮/触控缩放、拖动空白平移、缩放与适配全部节点按钮、28px连接点吸附、20px节点网格吸附、Shift/系统多选键多选及Delete/Backspace删除。Esc取消连线/关系草稿并清除选择，不作为删除键。删除房间同步删除其关系，固定入户不能移动或删除。

原节点ID、需求与采光设置不迁移，旧归一化图坐标仍按1000×700基准映射，允许超出原0～1范围扩展画布（仍有有限数值边界）。关系可保存diagramHandles用于连接端口恢复，Agent提示会移除这些纯图编辑字段。视口位置与缩放按会话/底图保存在浏览器偏好中，房间排版仍保存到需求版本。画布只控制图表达，不改变生成后的房间位置。

## 承重墙关系与公共主体

质量检查v3记录承重墙两侧空间归属、未说明用途的突出墙段与墙体接合，先预留公共主体再联合安排房间，按墙体关系、公共空间完整性、面积及窗偏好的顺序选择候选。求解报告提供表格与几何叠加；用户可在布局参数中声明开放空间墙垛的保留用途。算法边界、报告字段与截图回归见[承重墙与住宅空间关系](residential-wall-relationships.md)。

v4增加相邻隔墙的墙面连续对齐，识别短台阶，并在完整布局候选中调整房间边界后重建门墙、重新验证全部硬需求。对齐错位量的排序优先于公共主体和面积朝向偏好，报告以蓝色标记残余台阶。

v5修复承重墙与新隔墙接合：直线续接沿用固定墙中心线和厚度，T接/转角按实际墙面求交，净面积和显示使用一致接合几何。布局参数可编辑普通隔墙厚度（默认120mm），报告展示各接合的偏移与两墙厚度。

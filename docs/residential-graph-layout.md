# 住宅需求与节点图排版版本

节点坐标 `position` 和连线端点 `diagramHandles` 只控制图形排版。房间属性、关系端点/含义/优先级、布局求解参数、仿真目标/工况和补充要求属于需求语义。共享投影和版本规则位于 `shared/src/residentialGraphLayout.ts`。

## 存储与接口

固定底图目录的 `residential-brief.json` 使用存储 schemaVersion 2，在同一个文件中分开保存 `semanticBrief` 与 `graphLayout.data`。前者不含节点坐标或连线显示端点；后者按节点/关系 ID 索引排版数据。一次临时文件写入和 rename 同时保存两部分，不引入跨文件事务。

`version` / `updatedAt` 表示需求语义；`graphLayout.version` / `updatedAt` 表示排版。首次明确保存发布需求版本 1。之后只改排版时保持需求版本和时间不变；语义变化推进需求版本；同时改变两部分则分别推进版本。重复保存不推进任何版本。

GET/PUT 继续返回兼容的 ResidentialBriefDocument：`brief` 为语义和布局合成的编辑视图，新增可选 `graphLayoutVersion` / `graphLayoutUpdatedAt`。RoomRequirement.position 仍存在于兼容视图及历史冻结文档中，求解输入和身份摘要不使用它。PUT 同时检查 expectedVersion、expectedGraphLayoutVersion 与底图 hash。旧客户端省略布局版本时仅允许不覆盖已发布排版的写入。

旧内联文档读取时不改写；下一次成功保存迁移为新格式，并按实际变化决定是否推进版本。现有 generation-brief.json 历史冻结文件保持原样。Agent 需求解释工作目录中的 residential-brief.json 仍为原需求协议，不能与底图目录的存储格式混淆。

## 前端行为与缓存

节点拖动和仅调整连接显示端点标记为布局未保存，不标记需求未保存。界面分别提示并保存两类变化；布局未保存不阻止使用已保存的需求生成方案，也不会显示仿真目标已修改。编辑已有关系时保持数组顺序，避免显示端点变化附带改变语义顺序。

本地草稿使用同一版本规则。住宅生成控制器只因需求语义变化失效；生成前仍读取服务端最新需求版本。Agent 解释期间若需求版本已被其他写入推进，则拒绝覆盖；若只更新了排版，则保留最新排版并保存解释得到的需求。节点数/关系变化时布局索引随实际对象重新生成。

缓存身份只包含需求语义版本及其摘要，排版版本不参与。保存排版后原需求引用仍可用于生成，已有仿真结果不会因图形布局而过期。真实房间、关系含义、工况或规则变化继续按原身份机制失效。

## 验证范围

回归验证布局保存保持语义版本、缓存身份与生成准入；语义变化失效；原冻结文件不改写；旧格式读取/迁移；并发写入拒绝；本地草稿及重复保存；Agent 输入不受排版影响；解释期间合并新布局并拒绝新需求版本。前端 dirty 分类直接使用这些共享纯函数，React 编辑器尚未做浏览器挂载回归。

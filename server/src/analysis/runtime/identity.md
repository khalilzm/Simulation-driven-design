# 结果身份与失效规则

`shared/src/resultIdentity.ts` 定义结果身份，`identity.ts` 实现稳定摘要、缓存与可比性校验。住宅评价、候选采光试算和优化工作台使用同一套身份机制；通用工作区构造器支持底图/地图、空间节点与多个仿真实例。

## 输入与比较

身份记录会话、模型版本、模型语义摘要、底图和需求的 ID/版本/内容摘要、场景版本、规则版本、计划版本，以及每个模块的 ID、版本、能力、工况摘要和引擎版本。对象属性顺序不影响摘要；数组顺序保留；非有限数值和非 JSON 对象拒绝。

`inputHash` 包含模型版本和几何内容，用于判断同一结果能否复用。`comparisonHash` 排除模型版本和几何摘要，允许同一冻结条件下比较不同候选；仍保留会话及全部工况、资源和版本条件。相同身份只是比较的前提，优化策略继续检查采样、人数、目标和结果完整性。

空间节点的 `position` 和关系的 `diagramHandles` 属于排版，从需求语义摘要中排除。住宅保存接口已将排版版本与需求语义版本分离，单独保存排版不推进需求版本，也不改变缓存身份；见 [节点图排版版本](../../../../docs/residential-graph-layout.md)。历史候选依据生成时冻结的需求评价，不把当前编辑中的需求替换进历史任务。

## 缓存与历史记录

读取已完成评价时检查完整身份及结果报告的引擎版本；身份缺失、变化或损坏的记录显示过期，隐藏旧结果和判定。仅仅读取不改写历史文件。重新计算前将原记录保存到 `<评价文件>.history/<内容摘要>.json`，再通过临时文件与 rename 写入新记录；原引擎产物保留。当前没有新增历史浏览界面。

优化工作台复用基线时核对当前模型、保存的配置、计划、规则和引擎。采纳候选前重新校验基线与候选身份及引擎证据；旧记录仍可显式读取，但缺少完整身份时不能自动复用或作为性能改善的依据。

原 `JSON.stringify` 存储摘要仅用于旧模型文件完整性及历史引用兼容，不再用于新的结果缓存身份。新结果身份不要求迁移原文件摘要。

## 版本维护与边界

规则、计划和引擎版本由实现声明；改变算法、规则或依赖时必须更新相应版本，框架不会自动探测二进制或源码变化。优化策略还将完整策略参数摘要写入规则身份。引擎返回的版本必须与身份中的声明一致。

本阶段统一的是评价与优化结果身份；采光、日照与人流原始任务已采用 [公共 envelope](task.md)，物理结果保留原能力格式。地图资源适配、商业/办公场景和前端多模块配置仍需分别实现。住宅默认室内采光只是工作流预设，身份机制支持其他已实现能力及多个模块实例。

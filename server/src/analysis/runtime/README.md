# 公共评价生命周期

`evaluation.ts` 管理评价记录的缓存读取、输入过期、进程中断识别、同一记录的并发保护、取消、失败、完成及原子落盘。它不依赖具体场景、计算引擎或规则。

场景适配器提供输入快照及 hash、初始记录、分析函数、结果完整性校验和目标评价函数。结果与目标评价保留各自的类型：执行 completed 不表示目标 passed；取消/失败也不会改写设计几何。

当前住宅室内采光与历史直射日照评价均接入该生命周期，原结果文件路径和 API 保持兼容，记录新增结果身份。运行前已经取消的任务会保存 cancelled 状态，不启动引擎。同一文件的任务执行期间拒绝第二个任务，不同会话或不同评价文件可以独立执行；这里的锁为当前进程内的锁。

已完成记录在输入 hash、完整结果身份及引擎版本校验通过时复用。身份缺失或输入改变后读取为 stale，并隐藏旧结果及目标评价；running 记录在本进程没有对应活动任务时显示为中断失败，可重新执行。原子写入使用 .tmp + rename，结束时无论成功或失败都释放活动标记。

评价生命周期提取不改动物理算法与规则。后续已接入 [可配置分析计划](plan.md)：当前住宅验收默认验证室内采光，优化比较策略选择日照与疏散，由公共执行器按计划调用。住宅用途不限制可选能力，工作区可以配置多个仿真实例。当前比较策略依然要求日照保护与疏散改善；场景、规则、计划、模块和引擎版本已纳入 [结果身份](identity.md)，过期记录重算前保存原记录历史快照；采光、日照、人流原始任务已接入 [公共引擎任务封装](task.md)，保留各能力物理结果类型。

前端住宅控制器位于 `web/src/scenarios/residential/useResidentialBrief.ts` 与 `useResidentialEvaluation.ts`。公共 requestScope 用会话/版本上下文、选择轮次和请求通道拒绝迟到结果；模型替换也会使旧评价请求失效。保存完成后保留期间新增的编辑，异步评价运行状态与对话 busy 分开管理。

回归测试覆盖缓存失效、执行/目标状态区分、中断、并发、取消后重试、预取消不启动引擎，以及跨会话同版本号、切回旧对象、迟到读取和清理后的结果隔离。这里的前端测试直接验证请求作用域逻辑，未使用浏览器挂载 React 控制器。

住宅评价捕获公共任务异常时保留 taskId，失败记录可以关联到冻结输入、进程诊断与任务 envelope。目标是否通过仍由场景判定，公共任务 completed 不代替目标 passed。

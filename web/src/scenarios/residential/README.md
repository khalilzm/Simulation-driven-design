# 住宅前端模块

住宅需求、节点图、指标、生成准备和评价由本目录管理。App 装配白板、通用对话流、Viewer 和方案选择；住宅默认室内采光是当前工作流的前置条件，不是框架的能力限制。

## 生成与输入边界

- `generation.ts` 提供可独立测试的需求解释与生成准备：节点图结果作为指标解释的输入；指标解释失败时保留已完成节点图；只有实际存在的内容才发布白板。生成前验证底图、保存状态及服务端当前需求版本。
- `useResidentialGeneration.ts` 连接 API 与对话状态，管理解释、保存和准备请求的取消、会话/提供方/底图作用域，以及需求语义与底图对象变化后的失效。App 接收 `PreparedScenarioGeneration`，直接将场景引用和父版本交给通用 streamChat。
- `draftStorage.ts` 管理 DXF 上传前的本地草稿保留和上传后的关联；解析、读取或保存失败保留草稿。关联成功只删除所读取的原快照，期间新保存的本地内容继续保留。
- `baseModel.ts` 按候选的冻结输入引用解析底图；不能将其他底图的候选套到当前底图。App 在读取底图后再次核对会话与选择轮次，才更新选择状态。

工作台请求契约位于 `web/src/workbench/scenarioGeneration.ts`，不包含 ResidentialBrief。现阶段 App 仍装配住宅展示组件，也仍直接选择住宅控制器；商业/办公控制器、地图适配和前端多仿真实例配置没有作为空实现注册。

## 取消与回归边界

住宅 API 请求传递 AbortSignal。取消或输入变化停止后续解释/保存/生成步骤并拒绝迟到结果；已经到达服务端的写入不能由客户端取消保证回滚，应重新读取版本。解释模块仍使用现有 graph/metrics 输入协议。

服务端测试 `residentialGeneration.test.ts` 通过注入 API/存储/作用域校验验证完整顺序、部分失败、冻结引用、版本变化、取消及草稿关联；架构检查禁止 App 直接导入住宅输入持久化与需求解析操作。这些是逻辑与边界测试，没有浏览器挂载 React hooks。

需求版本与节点图排版版本已分离：拖动节点只标记布局未保存，保存布局不使仿真缓存过期；GET/PUT 合成原编辑视图，磁盘分开保存语义与排版。协议、迁移与并发处理见 [节点图排版版本](../../../../docs/residential-graph-layout.md)。
